# Neon Arcana — План разработки

**Версия:** 1.0  
**Дата создания:** 2024

---

## Обзор

Этот документ описывает поэтапный план разработки игры Neon Arcana — браузерной мультиплеерной стратегии в реальном времени.

---

## Этап 1: Технический прототип

**Длительность:** 1-2 недели  
**Цель:** Проверить core gameplay без графики и сети

### 1.1 Настройка проекта

- [ ] Инициализация TypeScript проекта
- [ ] Настройка сборщика (Vite/Webpack)
- [ ] Настройка HTML5 Canvas для рендеринга
- [ ] Базовая структура файлов и папок
- [ ] Настройка линтера и форматтера

### 1.2 Базовые классы и архитектура

- [ ] `Game` — главный игровой цикл
- [ ] `Unit` — базовый класс юнита
- [ ] `Tower` — башня игрока
- [ ] `Road` — дорога между башнями
- [ ] `Player` — состояние игрока

### 1.3 Минимальный геймплей

- [ ] Одна карта с 2 башнями (левая и правая)
- [ ] 1 тип юнита (разведчик)
- [ ] 1 прямая дорога между башнями
- [ ] Базовая боевая система (HP/DPS)
- [ ] Управление: клик для создания юнита, клик по дороге для отправки

### 1.4 Тестирование

- [ ] Локальный режим: 2 игрока на одном экране (split controls)
- [ ] Или: AI-болванка для тестирования
- [ ] Проверка core loop: создание → движение → бой → атака башни

### Критерии завершения этапа 1

✅ Можно создать юнита  
✅ Юнит движется по дороге  
✅ Юниты сражаются при встрече  
✅ Юнит атакует вражескую башню  
✅ Башня может быть уничтожена

## Технические исследования (перед этапом 1)

Перед началом разработки необходимо провести исследование:

### Вопросы для исследования

1. **Рендеринг:** Canvas 2D vs WebGL vs PixiJS vs Phaser
2. **Сборщик:** Vite vs Webpack vs Parcel
3. **Архитектура:** ECS vs OOP vs Hybrid
4. **Сетевой стек:** Socket.io vs ws vs Colyseus
5. **Серверная платформа:** Node.js vs Deno vs Bun
6. **State management:** Как синхронизировать игровое состояние

Будет записан в отдельный документ: `docs/tech-research.md`
